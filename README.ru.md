# agent-audit

[**English**](README.md) | [**Русский**](README.ru.md)

**Консольный аудитор и навык (`SKILL.md`) для анализа сессий OpenAI Codex (`codex`) и Google Antigravity (`agy`).**

Утилита работает без внешних библиотек, веб-интерфейсов и фоновых служб. Она читает локальные базы SQLite и JSONL-логи агентов **строго в режиме чтения**, не выводит значения секретов из `.env` и за пару секунд собирает отчёт в Markdown или JSON: реальный расход некэшированных токенов, попадание в кэш, рентген раздувания контекста, повторяющиеся раскопки в файлах и сбои инструментов.

Запускать можно вручную из терминала или прямо через агента в CLI — попросив его самого найти узкие места и починить правила, навыки или обёртки.

---

## Зачем это нужно

Когда на машине или сервере постоянно работают консольные агенты (`codex`, `agy`) и запускают дочерних субагентов, по сырым логам трудно понять, куда уходит квота и почему проседает скорость:

1. **Разный учёт токенов у разных агентов:**
   - В **Codex** (`~/.codex/sessions/**/*.jsonl`) поле `input_tokens` *уже включает* кэшированный вход (`cached_input_tokens`), `output_tokens` *включает* `reasoning_output_tokens`, а логи субагентов без дедупликации по `token_usage_record.response_id` могут считаться дважды.
   - В **Antigravity (`agy`)** (`~/.gemini/antigravity-cli/brain/*/.system_generated/logs/transcript.jsonl`) поле `input_tokens` — это *только некэшированный* вход, а чтение из кэша лежит отдельно в `cache_read_tokens`.
2. **Один неудачный шаг стоит дороже 50 обычных:** неограниченный `git diff` на `80 КБ`, чтение файла на 3000 строк целиком без границ `StartLine`/`EndLine` или сброс префиксного кэша на длинной сессии сжигают за один ход больше некэшированной квоты, чем полчаса аккуратной работы.
3. **Агенты из сессии в сессию делают одну и ту же ручную работу:** десятки раз вытаскивают `DATABASE_URL` из `.env`, по 6 раз за одну задачу перечитывают один и тот же монолит или крутят в цикле `gh pr checks`, вместо того чтобы вызвать готовую утилиту.

## Установка

Нужен только **Python 3.10+** (используется стандартная библиотека).

```bash
git clone https://github.com/gmen1057/agent-audit.git
cd agent-audit

# 1. Установить CLI-команду
chmod +x agent_audit.py
sudo ln -sf "$PWD/agent_audit.py" /usr/local/bin/agent-audit
# (либо через `pipx install .` / `uv tool install .`)

# 2. Подключить навык к Codex и Antigravity, чтобы агенты умели сами запускать аудит
mkdir -p ~/.codex/skills/agent-audit
cp skills/agent-audit/SKILL.md ~/.codex/skills/agent-audit/SKILL.md

mkdir -p ~/.gemini/antigravity-cli/skills/agent-audit
cp skills/agent-audit/SKILL.md ~/.gemini/antigravity-cli/skills/agent-audit/SKILL.md
```

## Быстрый запуск из консоли

```bash
# Сводка за последние 7 дней на русском языке
agent-audit --lang ru

# Сводка на английском (по умолчанию)
agent-audit

# За 30 дней или за всю доступную историю
agent-audit --days 30 --lang ru
agent-audit --all --lang ru

# Прицельно по одному проекту
agent-audit --days 14 --project billing-api --lang ru

# Короткая JSON-сводка для скриптов
agent-audit --json

# Сохранить отчёт в файл (создаётся с правами 0600)
agent-audit --days 7 --lang ru --output /tmp/agent-audit-latest.md
```

## Как анализировать отчёт вместе с агентом в CLI

Главная идея `agent-audit` — не просто смотреть на таблицы, а поручать самому агенту разбор отчёта и точечную починку окружения. После копирования `SKILL.md` достаточно написать агенту в чат обычный запрос.

### Сценарий 1. Разбор расхода токенов за неделю и быстрые правки

Напишите агенту (`codex` или `agy`):

> *«Запусти `agent-audit --days 7 --lang ru`, посмотри, на чём мы теряем больше всего некэшированных токенов, и предложи 3 конкретных исправления в наших скриптах или правилах».*

Что делает агент по инструкции из `SKILL.md`:
1. Смотрит на колонку **Вход БЕЗ кэша** (именно она отражает реальную нагрузку на квоту и деньги, в отличие от дешёвого чтения из кэша).
2. Сверяет **раздел 2** (повторяющиеся чтения `.env` и `rg`), **раздел 3** (процент брака MCP и циклы повторов) и **раздел 4** (разовые скачки контекста, чтения файлов целиком и расход на субагентов).
3. Предлагает конкретные действия — и после вашего «да» сам правит конфиги, скрипты или `AGENTS.md`.

### Сценарий 2. Убрать ручное чтение `.env` и обход штатных утилит

Если в **разделе 2** видно, что агенты в 10+ сессиях подряд читают `backend/.env` ради `DATABASE_URL` или `SENTRY_AUTH_TOKEN`:

> *«Посмотри раздел 2 в `agent-audit`. Агенты постоянно лазят в `backend/.env` за `DATABASE_URL` и ходят в базу прямым `psql`. Сделай безопасную read-only утилиту `/usr/local/bin/db-query`, которая сама подхватывает `.env` без вывода ключей в консоль, пропиши её в `AGENTS.md` и добавь правило контроля в `~/.config/agent-audit/config.json`».*

Через пару дней повторный запуск `agent-audit` сразу покажет, перестали ли агенты лазить в `.env` и ходить в обход утилиты.

### Сценарий 3. Починить ошибки MCP и циклы ожидания CI

Если в **разделе 3** у MCP-инструмента `20%` ошибок из-за `input validation error (wrong arg name)` или виден цикл `gh pr checks <PR>`:

> *«В `agent-audit` видно 20% ошибок у `codegraph.callers_of` из-за имени аргумента и циклы опроса `gh pr checks`. Добавь алиас аргумента в MCP-сервер, чтобы агент не терял шаги на ошибку схемы, и сделай скрипт `/usr/local/bin/ci-wait` для ожидания проверок PR одной командой».*

### Сценарий 4. Разгрузить контекст и убрать провалы кэша (`Section 4`)

Если сессии в проекте часто уходят в автосжатие (`contextCompaction` / `CHECKPOINT`) или долго думают:

> *«Проверь проект `web-studio` через `agent-audit --days 14 --project web-studio --lang ru`. Из-за каких файлов и команд в 4-м разделе происходят скачки контекста и перечитывания?»*

Как читать цифры 4-го раздела:
- **Много чтений целиком (`:FULL`) и перечитываний одного файла `≥4 раз` за сессию:** файл разросся в монолит или агенту не хватает карты проекта (`MAP.md`), поэтому он выгружает весь файл в контекст. Решение: добавить в `AGENTS.md` правило читать файлы `>400` строк по диапазону (`StartLine`/`EndLine`) после точного поиска символа.
- **Выводы команд `>30 КБ` и скачки после `git diff`:** добавить правило вызывать сначала `git diff --stat` или указывать путь к конкретному файлу.
- **Большая доля некэшированного входа у субагентов (раздел 4.4):** каждый новый субагент прогревает контекст заново. Если родительская сессия плодит по 5–6 помощников на мелкие вопросы, ограничьте в `AGENTS.md` запуск субагентов только крупными независимыми задачами.

## Необязательная настройка (`~/.config/agent-audit/config.json`)

По умолчанию настройка не нужна: `agent-audit` сам находит `~/.codex` и `~/.gemini/antigravity-cli`, а имя проекта определяет по рабочей папке сессии.

Если у вас несколько папок профилей агентов, свои правила группировки проектов или свои внутренние утилиты, скопируйте [`config.example.json`](config.example.json) в `~/.config/agent-audit/config.json`:

```json
{
  "codex_homes": [
    "~/.codex"
  ],
  "agy_roots": [
    {
      "label": "default",
      "path": "~/.gemini/antigravity-cli"
    }
  ],
  "projects": {
    "my-webapp": ["my-webapp", "webapp-frontend", "webapp-backend"],
    "infra": ["terraform", "ansible", "k8s"]
  },
  "bypass_rules": [
    {
      "name": "Прямой psql вместо безопасной обёртки БД",
      "pattern": "\\bpsql\\b|asyncpg\\.connect|psycopg2",
      "unless": "db-safe-query"
    }
  ]
}
```

## Безопасность

- **Только чтение:** базы SQLite открываются с флагом `?mode=ro` (`uri=True`), файлы сессий никогда не изменяются.
- **Секреты не попадают в отчёт:** при анализе обращений к `.env` собираются только пути к файлам и имена переменных (`DATABASE_URL`, `STRIPE_SECRET_KEY`), но никогда не их значения. Длинные токены в поисковых запросах автоматически заменяются на `<REDACTED>`.
- **Защита файлов отчёта:** при сохранении через `--output` файл создаётся с правами `0600` (чтение только для владельца).
